开始使用

  1. 复制最新正式版安装地址，在 Surge「模块」中选择「从 URL 安装」。
  2. 填写目标接口的 URL 正则和修改参数，点击「应用」并启用模块。
  3. 调试 HTTPS 时，启用 MITM、添加目标主机名，并让测试设备信任同一份 Surge 证书。
  4. 重新触发接口，在请求的 Notes 中检查 API Debug 日志和修改后的内容。
https://github.com/evenlinyf/surge-api-debug/releases/latest/download/surge_api_debug.sgmodule

如果还不知道 URL 或 JSON 字段，先看 Surge Mac 给手机抓包指南。

快速示例：只让第一次响应返回 HTTP 500

url=^https://api\.example\.com/v1/profile$
direction=response
target=status
action=set
path=$
value=500
value_type=number
hit_limit=1
delay_ms=0

此例只修改状态码；要替换整个 Body，使用 target=body 和 path=$。

1. 参数模型

url

指定要命中的接口。

direction

request / response。

target

body / header / url / status。

action

set / format / remove / mock / abort。

参数说明
url匹配完整请求 URL 的正则，例如 ^https://api\.example\.com/v1/messages$。
directionrequest / response
targetbody / header / url / status
actionset / format / remove / mock / abort
pathBody 下是 JSON Path，使用 $ 表示整个 Body，数组下标必须写成 [n] 且已存在，越界时不修改响应；也可用 [?(@.field == value)] 筛选。Header 下是 Header 名。
value新值；使用 @empty 表示空字符串。action=format 时，${old} 表示当前字段的原值。& 可直接输入，例如 A&B；%26 也仍可使用。
value_typestring / number / boolean / null / json
hit_limit生效次数。0 或留空表示每次生效，3 表示只在前 3 次生效，-3 表示从第 4 次起每次生效。
delay_ms0 ~ 25000，可叠加到任意操作。

2. 合法组合

directiontargetaction用途
requestbodyset / format / remove修改 Request Body / JSON；format 仅限已有的字符串字段。
requestheaderset / remove修改 Request Header。
requesturlset修改 Request URL。
responsebodyset / format / remove修改 Response Body / JSON；format 仅限已有的字符串字段。
responseheaderset / remove修改 Response Header。
responsestatusset修改 HTTP Status。
request忽略mock直接返回 HTTP 200 Mock Response。
request / response忽略abort中断链路。
path 的语义由 target 决定：body → JSON Path（$ 表示整个 Body）；header → Header 名；url/status 不使用 path。Module 参数中的 path 和 value 不要留空，不使用时也要填写明确的占位值。

3. Body 修改

修改 JSON 字段

url=https://api.example.com/api/messages
direction=response
target=body
action=set
path=data.items[0].content
value=debug-content
value_type=string

字段设为空字符串

direction=response
target=body
action=set
path=data.version
value=@empty
value_type=string

按数组元素筛选并修改

direction=response
target=body
action=set
path=data.items[?(@.id == 42 && @.role == 'member')].content
value=@empty
value_type=string

引用原值并在前面加文字

direction=response
target=body
action=format
path=data.items[?(@.id == 42)].content
value=【已修改】${old}
value_type=string

字段设为 null

direction=response
target=body
action=set
path=data.user
value=ignored
value_type=null

数组设为空

direction=response
target=body
action=set
path=data.items
value=[]
value_type=json

删除字段

direction=response
target=body
action=remove
path=data.user.avatar
value=ignored
筛选中的 @ 表示当前数组元素；支持数字、字符串（建议单引号）、布尔值和 null，以及 ==、!=、大小比较、&&、|| 和括号。每条 path 支持一个筛选器，后面必须跟要修改的字段；所有可写的匹配项都会修改，缺少目标字段或父路径的项会跳过，完全未命中时保持响应不变。不支持函数或完整 JSONPath。format 会为每条命中的字符串分别使用其原值；value=前缀${old}后缀 可同时在两边加文字。${old} 仅是占位符，不会执行 JavaScript；set 仍按字面量写入。

替换整个 Body

target=body + action=set 且 path=$ 时，替换整个 Body。

direction=response
target=body
action=set
path=$
value={"code":0,"data":null}
value_type=json

4. Header / URL / Status

设置 Header

direction=request
target=header
action=set
path=Authorization
value=Bearer debug-token

删除 Header

direction=request
target=header
action=remove
path=Authorization
value=ignored

修改 URL

direction=request
target=url
action=set
path=$
value=https://api.example.com/api/mock

修改 Status

direction=response
target=status
action=set
path=$
value=500

5. Mock / Abort / Delay

Mock Response

url=https://api.example.com/api/profile
direction=request
action=mock
path=$
value={"code":0,"data":{"name":"debug"}}
value_type=json

Abort

direction=response
action=abort
path=$
value=ignored
delay_ms=0

延迟后返回 500

direction=response
target=status
action=set
path=$
value=500
delay_ms=5000
delay_ms 是独立修饰参数，可与 set / format / remove / mock / abort 组合。仅在操作应用时延迟，未命中、配置错误和次数跳过时不延迟。

限制生效次数

面板只读显示当前进度：正数为“已生效 N 次，剩余 M 次”，负数为“已跳过 N/M 次”或“已进入持续生效阶段”，不限次数为“不记录次数”。自动刷新不消耗次数、不清零；存储异常会显示错误，计数损坏可手动刷新清零恢复。

例如，只让匹配接口的前 3 次响应返回 500。要跳过前 3 次，从第 4 次起持续返回 500，把下例的 hit_limit 改成 -3。

url=https://api.example.com/api/profile
direction=response
target=status
action=set
path=$
value=500
value_type=number
hit_limit=3

Surge 先按 URL 匹配，脚本再确认操作是否适用。筛选没有匹配项、路径不可写、要删除的字段或 Header 不存在时不计数。一个请求即使修改多个数组元素，也只算一次。因次数限制跳过的请求直接放行，配置的延迟也不执行。

重置次数在 Surge 信息面板中打开「重置次数」并点一下刷新图标，看到「已清零，下次命中从头计数」即可。Mac 从 Surge 菜单栏的「面板」进入，iOS 在策略选择页查看。hit_limit 保持原值，面板会显示对应的 URL 正则与方向，点击时只清除这一组合的计数，其他接口和方向不受影响。重新打开面板时会恢复操作提示；自动刷新提示不会清零。Surge 信息面板文档

每个完整 URL 正则与方向的组合单独保存计数。使用新的正则时从头开始，切回之前的正则则继续它的原有计数。修改非零限额后，该规则下一次符合条件的请求从头计数。同一条正则匹配的不同请求地址共用限额。请求和响应各自计数，关闭再开启 Module 或只修改路径、值等参数会保留计数。也可以把 hit_limit 改成 0，发一条满足条件的请求清零，再改回限额。清零的这条请求会执行操作。

顺序请求按上述次数执行。多个请求同时命中时，Surge 的持久化接口没有提供原子计数操作，结果可能与设定次数有出入。Surge 脚本 API

6. 多个模块修改不同接口

面板根据 URL 正则、方向和 hit_limit 自动生成唯一标识，点击时由固定名称的 reset 脚本还原对应的重置属性，无需填写额外名称。标题显示配置的 hit_limit，正文显示接口、方向和次数含义。各实例的 Module 和 JS 需一起更新。

模块在 Surge 中归入 Dev 分类。

给安装链接添加不同的查询参数，可以安装多个独立实例。它们共用一份 JS，在 Surge 中分别填写各自的接口 URL 和修改内容：

https://github.com/evenlinyf/surge-api-debug/releases/latest/download/surge_api_debug.sgmodule?name=login
https://github.com/evenlinyf/surge-api-debug/releases/latest/download/surge_api_debug.sgmodule?name=messages

?name=... 只区分安装链接，不会自动传入参数或更改显示名称，不需要在模块里再填写名称属性。

参数登录接口消息接口
url^https://api\.example\.com/v1/login$^https://api\.example\.com/v1/messages$
directionresponseresponse
target / actionbody / setbody / set
pathdata.versiondata.message
value@empty调试消息
value_typestringstring
hit_limit13

按完整 URL 正则和方向隔离计数、重置范围。不同安装链接若填写相同正则和方向，仍共用计数。一次请求匹配同一正则的不同具体 URL，也共用该正则的限额。

此功能用于不同接口，正则不要重叠。同一方向只运行首个匹配的 HTTP 脚本；一份模块仍只有一组 path / value，暂不支持通过多个模块同时修改同一接口的不同字段。

7. 版本与安装地址

普通安装使用 GitHub 最新正式 Release 附件；需要保持某个版本时，使用带版本号的 Release 地址。固定版 Module 会引用同一 Git 标签下的 JS，不需要另外上传 JS 附件。

最新正式版

https://github.com/evenlinyf/surge-api-debug/releases/latest/download/surge_api_debug.sgmodule

固定版本

https://github.com/evenlinyf/surge-api-debug/releases/download/v1.0.0/surge_api_debug.sgmodule

正式版本从 1.0.0 开始，包含多模块隔离、独立重置面板、次数进度和调试日志。固定版本需在对应 Release 发布后使用。所有已发布版本见 Releases。

Module 和 JS 的版本需要一致。安装 Module 后，Surge 会自动下载它指定的 JS：

script-path=https://raw.githubusercontent.com/evenlinyf/surge-api-debug/v1.0.0/surge_api_debug.js
module_version=1.0.0

版本一致时日志包含 script_version=1.0.0, module_version=1.0.0。版本缺失或不一致时保持请求或响应不变，日志会提示 version mismatch；重新安装配套版本即可。

8. 排查

日志使用 [已应用]、[已跳过]、[配置错误]、[执行错误] 和 [状态] 标记结果。筛选修改会列出 matched/changed/skipped 数量及跳过原因；配置错误会给出参数示例。

value 中合法的百分号转义只解码一次，可与普通百分号混用：100% A%26B 得到 100% A&B。保留字面量 %26 时写 %2526；无效 UTF-8 转义保持原样。path 和 URL 正则不参与 value 解码。

没命中

检查 url、direction 与 MITM。

字段没改

检查 path 是否匹配真实 JSON。

次数没重置

在对应接口的「重置次数」面板手动点刷新并查看结果。

value 异常

检查 value_type；& 可直接输入，或写成 %26。普通百分号无需处理。

确认执行

在 Script / Notes 查看 [Surge API Debug] 日志。
